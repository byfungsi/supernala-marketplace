# Phase 1 compatibility

The Marketplace contract retains the committed Phase 1 integration baseline and additionally pins the exact reviewed Workspace-owned OAuth authority reset. This compatibility reference does not claim deployment; `compatibility/phase-1-sources.json` pins the exact application files.

The portable implementation preserves the two runtime descriptors, branded identity constraints, canonical JSON digesting, ZIP safety limits, package manifest/catalog/config semantics, private R2 object-key formula, and internal publication input shape. No absolute import or file dependency points at the application repository.

The application exposes packaged publication only through internal D1/R2 capabilities; there is no authenticated production publication endpoint. Additive migration `0051_workspace_owned_oauth_authority.sql` removes live deployment-material authority only when no retained old-model rows exist, converts credential-free OAuth registrations to `workspace-oauth-app`, and requires each runtime attempt to pin one Workspace OAuth App and Plugin Vault reference. The Marketplace trusted release adapter validates reviewed provider files, admits only credential-free Provider Definitions and Registrations, and then publishes through documented Cloudflare D1/R2 interfaces. It remains disabled until exact credentials, environment topology, migration, release set, and operator approval are supplied; Cloudflare D1 tokens are not assumed to enforce table-level authority.

Pinned Phase 1 resolves Config schemas by exact digest, revision, and recursively strict canonical fields, reuses the actual persisted identity (including legacy IDs), and assigns new rows `config:sha256:<digest>`. Concurrent alternate-ID winners are accepted only after rollback and exact bounded re-resolution. Migration `0042_plugin_control_plane.sql` retains the accepted SQL digest, and Phase 1 is not modified here.
