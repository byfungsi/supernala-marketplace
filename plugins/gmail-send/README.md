# Gmail Send (Owner-authorized publication-ready candidate)

Separate managed-package identity `supernala/gmail-send` version `0.1.0`, intended as a send method in the Gmail integration family. It does not alter the existing `supernala/gmail` read-only package, installation, connection, or grants. The Owner has authorized this candidate for publication eligibility after application production revision `d4e145e` was reported healthy. Eligibility does not mean the package has been published or that live Gmail consent or sending has been accepted. Formal digest-bound review and the trusted publication workflow remain separate gates.

The sole tool `gmail.send_message` posts one bounded, validated, plain-text MIME email via `users.messages.send`. No drafts, attachments, HTML, alias-listing, read tools, or retry logic are included. The caller supplies an explicit `from` address, one recipient, subject, and body. Gmail enforces ownership or verified send-as aliases; the send-only scope cannot list aliases, so this tool does not claim the sender is authorized before dispatch. A successful response returns only the Gmail message ID. A transport failure or unreadable success response can mean the email was sent; the caller must reconcile manually rather than automatically repeating it. Gmail does not provide an idempotency key for this endpoint, so caller replay is not exactly-once.

The distinct `google-gmail-send-rest-v1` Provider Registration is `workspace-oauth-app`, using Owner-supplied Google OAuth client ID and secret stored only in the application's encrypted Plugin Vault. Public source declares fields and binding names, never values. It requests `openid`, `email`, and **only** `https://www.googleapis.com/auth/gmail.send` among Gmail mailbox permissions. The OIDC scopes are required for the generic account projection at `https://openidconnect.googleapis.com/v1/userinfo`, with stable `sub` and display email. Google's Gmail `users.getProfile` does not document `gmail.send` as an accepted scope. This identity must not be inferred from another Gmail Connection.

Google may return `https://www.googleapis.com/auth/userinfo.email` as an alias for `email` (and may include both); application revision `d4e145e` is reported healthy in production, but a live consent/refresh flow has not yet established the behavior for this send registration. The provider definition's canonical digest and the packaged OAuth authority are validated offline, but offline validation does not establish live OAuth or delivery acceptance. A new send connection requires installation, consent, Workspace activation, and Agent Grant; existing read-only users need not reinstall their read-only method.

Only first-party source is packaged. Google's services, content, and trademarks are not relicensed by this repository.
