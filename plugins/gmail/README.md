# Gmail managed-package candidate

First-party source for four read-only Gmail capabilities: search message identities, read one message, list draft identities, and read one draft. Every tool is classified `read` and defaults to the existing `require-approval` policy. Installation, OAuth Connection consent, and Agent Grant remain separate mandatory controls.

The package requests only `https://www.googleapis.com/auth/gmail.readonly`. It does not expose create, update, send, delete, trash, label, settings, alias, or import operations. Search/list calls do not fetch message bodies. Get calls return bounded normalized text and metadata with explicit truncation flags; email content is untrusted data, never instructions. Raw MIME, active HTML, remote content, and attachment bytes are not returned.

`oauth-provider.json` is provider-owned declarative source. Strict decoding and canonical re-encoding give the reviewed definition identity `3136b19f7d4b6f3b6597f75c42895bec8b41ab46bd5a984b39f4497ca6a6bc07`; that canonical digest is intentionally different from the ordinary formatted source file's raw SHA-256. The package archive binds the canonical digest but does not include or admit the definition. Definition and registration admission remain independent App deployment decisions.

The definition deliberately requests `access_type=offline` and `prompt=consent` so a new consent asks for refresh authority even when Google has seen the user before. Its `1..86400` access-token lifetime is a fail-closed source acceptance bound, not a promise about Google's actual lifetime and never extends a token. The Gmail profile exposes only `emailAddress` under the sole scope, so the projected subject and display label are explicitly mutable metadata rather than an application security principal. A later runtime may update metadata on the same already-bound Connection after authority checks, but must never auto-link Connections by email or mutate another Connection merely because subjects match. The 160-character display bound fails closed rather than truncating identity.

Disconnect must first fence this Connection locally, then may attempt one best-effort token-only revocation of its selected refresh token without ambiguous replay. Google documents that revocation can affect the authorization grant, and upstream effects may include other grants in the same Google project; this source does not claim isolated upstream revocation.

This candidate is **not publishable**. The generic OAuth runtime, durable callback/refresh/disconnect integration, definition and registration admission, trusted operator provisioning, encrypted token and client custody, Google restricted-scope verification or applicable exception, protected release review, and controlled live acceptance remain separate prerequisites. No functioning generic Gmail Connection or encrypted Plugin Vault is established by these files. The approved names `GOOGLE_GMAIL_OAUTH_CLIENT_ID`, `GOOGLE_GMAIL_OAUTH_CLIENT_SECRET`, and `GOOGLE_GMAIL_OAUTH_CALLBACK_URL` are declarations only; naming them here does not provision credentials or make a Google Connection runnable. No package, pull-request, build, or publication job receives those values. Only after separately approved provisioning, Owner installation, Workspace activation, Connection consent, and Agent Grant may the Actor-owned short-lived token be delivered to the Host as `PLUGIN_ACCESS_TOKEN`.
